# P0-ARC-002 — Electron/TypeScript bounded stack spike

- Owner: `/root/product_risk_review`
- Objective: determine whether a narrowly isolated Electron/TypeScript control plane can satisfy Alpha installer/configurator needs; this is evidence, not the production stack decision.
- Product boundary: the tool installs, detects, configures, compiles and hands off. MiniMax H3 generates video and native audio inside ComfyUI only after user Run.
- Accepted inputs: `AGENTS.md`, ADR-001, optimized architecture, runtime topology evidence.
- Allowed writes: `prototypes/phase0/stack-electron/**`, `docs/evidence/STACK_ELECTRON.md`.
- Forbidden writes: root plan, registry, schemas, root package/build files, other prototypes.
- Locks: none; dependencies and package lock must remain inside the isolated prototype. Any future root build/lockfile integration is a separate serialized task.
- Forbidden actions: no model download, GPU/H3 execution, Comfy/Desktop install, cloud inference, updater service, global package/runtime mutation or user-file changes.
- Required evidence: main/renderer isolation; context isolation and no renderer Node exposure; typed/allowlisted IPC; safe argument-array owned child; Unicode/space path behavior; packaging/signing/no-updater notes; accessibility surface; exact dependency and SBOM footprint.
- Acceptance: the prototype's documented install/build/test commands pass from its own directory, and the report states supported, unsupported and unresolved production requirements.
- Failure fallback: preserve reproducible evidence and mark the stack unsuitable or conditional; do not silently widen privileges.
- Unlocks after root acceptance: comparison with P0-ARC-003/004 and P0-ARC-005 technology-stack ADR.
