# P0-ARC-010 — Managed process/network ownership ADR

- Owner on dispatch: `/root/installer_plan_review` unless Root reassigns.
- Objective: turn accepted runtime-topology invariants into a Windows launcher/identity/network protocol and bounded fake-process proof.
- Product boundary: this task owns and verifies a managed Comfy process envelope; it does not generate media, click Run or submit `/prompt`.
- Dependencies: accepted P0-ARC-006 and ADR-002; consume accepted ADR-009 resource leases. P0-ARC-012 already proves fake lease semantics but not real process containment.
- Allowed writes: `docs/adr/ADR-012-managed-process-network-ownership.md`, `prototypes/phase0/managed-process-ownership/**`.
- Forbidden writes: registry, schemas, main plan, production stack projects, Comfy/model files and external instances.
- Locks: none; fake local children and loopback sockets only. No GPU, Desktop, VM, model or network download.
- Required protocol: generation/process/instance/run correlation IDs; strong random launch token; reserved loopback address/port transfer; backend/frontend/schema identity; Create-suspended→assign non-breakaway `KILL_ON_JOB_CLOSE` Job→verify→resume or a demonstrated equivalent; owned shutdown and timeout escalation; PID-reuse-safe creation identity; child/grandchild containment; allowlisted process image/generation roots; stdout/stderr redaction; loopback-only bind; external egress denial/capture boundary; crash and orphan handling.
- Required negative tests: pre-assignment child escape, breakaway flags, nested/pre-existing Job, PID reuse, stale token, wrong process image, wrong port owner, wildcard/non-loopback bind, child egress attempt, shell metacharacter arguments, parent crash, shutdown timeout and unrelated-process preservation.
- Acceptance: fake helper suite passes twice and proves no third-party instruction executes before containment; every impossible/unsupported Job configuration fails closed. Public results contain no private absolute paths or tokens.
- Evidence classification: native fake-process behavior may be proven; Comfy/Python/H3 behavior remains inferred until a later managed runtime test.
- Failure fallback: keep the runtime evidence-only and process disabled; never replace containment with “start then quickly attach.”
- Unlocks after Root acceptance: P2-INS-013 and QA-005; constrains QA-009.
