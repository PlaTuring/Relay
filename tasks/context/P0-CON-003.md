# P0-CON-003 — Component manifest and provenance schema

- Owner on dispatch: current `SCHEMA` lock holder.
- Objective: define immutable, license-aware artifact manifests for runtime, frontend, nodes, models and private tools without implementing downloads.
- Product boundary: contracts/fixtures only; no network, installation, model materialization, updater or media generation.
- Dependency: Root-accepted P0-CON-001.
- Allowed writes: `schemas/component-manifest/**`, `tests/fixtures/contracts/component/**`, `docs/evidence/COMPONENT_MANIFEST_SCHEMA.md`.
- Forbidden writes: registry, other schema families, root plan, downloader/installer implementation.
- Lock: `SCHEMA`.
- Required fields/invariants: component ID/version/role/platform/architecture; immutable revision/source locator; expected byte length and SHA-256; creator vs packager; origin/provenance chain; license ID/text/notice/source obligations and review state; filename/content type/archive shape; destination class without absolute user path; ownership/deletion authority; optional signature metadata; dependency edges; offline availability; revocation/supersession; catalog/app-version binding; no `latest/main` or remote catalog lookup.
- Required hostile fixtures: missing length/hash; mutable ref; wrong role; ambiguous creator/packager; absent license decision; path traversal/ADS/device/reparse intent; hash/size mismatch metadata; duplicate/conflicting ID; dependency cycle; unknown execution-affecting field; external artifact falsely marked tool-owned.
- Acceptance: deterministic offline validation command passes valid role examples and rejects each negative fixture with exact rule IDs; schema cannot authorize a download or deletion by itself.
- Failure fallback: artifact remains unavailable/unapproved and installer cannot materialize it.
- Unlocks: P0-CON-004, P1-DET-008, P1-DET-009 and P2-INS-002.
