# P0-CON-004 — Minimal Alpha recipe schema

- Owner on dispatch: the sole current `SCHEMA` lock holder.
- Objective: define one immutable, reconstructable Alpha recipe that pins the selected control plane, managed Core/backend/frontend, exact local-node fingerprints, FL2VA/base model roles, hardware profile and output capability.
- Product boundary: schema, synthetic fixtures and offline validators only. No model/runtime download, ComfyUI start, GPU, `/prompt`, first-job submission or media generation.
- Dependencies: Root-accepted P0-CON-001, P0-CON-002 and P0-CON-003 with their exact schema IDs and content digests.
- Allowed writes: `schemas/alpha-recipe/**`, `tests/fixtures/contracts/recipe/**`, `docs/evidence/ALPHA_RECIPE_SCHEMA.md`.
- Forbidden writes: other schema families, registry, plans, installer/downloader/workflow implementation, model files and root lockfiles.
- Lock: `SCHEMA`; exactly one worker.
- Required state boundary: the synthetic Alpha-0 T2VA/5-second/non-empty-prompt profile remains `poc_pending` and non-runnable because current capability/component evidence is pending/blocked. Recipe data cannot promote capability, component, legal, hardware or output status.
- Required exclusions: Desktop, cloud/API/Partner nodes, long video, Ref2VA, accelerators, self-update and private FFmpeg are absent unless an independently accepted capability requires them. The recipe grants no download, materialization, execution, ownership, deletion or queue authority.
- Required negative fixtures: schema/hash drift, mismatched app/runtime/frontend/node/model/hardware/output identities, blocked component or `poc_pending` capability marked runnable, missing prerequisite, unknown execution field, mutable revision, FFmpeg added without capability and any formal `/prompt`/auto-run field.
- Acceptance commands from repository root:

  ```powershell
  node --check .\tests\fixtures\contracts\recipe\validate.mjs
  node .\tests\fixtures\contracts\recipe\validate.mjs
  npm test
  ```

  Expected: exit `0`; validator prints exact schema digest, one non-runnable valid profile and deterministic negative-case counts; the root fast lane remains fully green. Repeat the validator twice with identical summary output.
- Evidence level: schema behavior may become `proven`; the actual H3 recipe remains `poc_pending` until later real runtime/GPU certification.
- Failure fallback: no recipe is runnable or selectable; do not weaken upstream statuses or invent compatible artifacts.
- Unlocks after Root acceptance: P1-DET-010, P1-DET-011 and later wheelhouse/runtime recipe work; it does not itself unlock GPU use.
