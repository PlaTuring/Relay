# P0-CON-001 — Contract conventions and compatibility

- Owner: `/root/workflow_plan_review`
- Objective: freeze the shared serialization and compatibility rules before any product schema is authored.
- Product boundary: contracts describe installation/configuration/workflow handoff only. They must not create a tool-side inference or automatic `/prompt` path; MiniMax H3 remains the sole media generator after the user clicks Run in ComfyUI.
- Accepted inputs: `AGENTS.md`, `docs/adr/ADR-001-product-process-boundary.md`, accepted `docs/adr/ADR-002-runtime-topology.md`, `docs/OPTIMIZED_ARCHITECTURE.md`, `docs/DECISION_LOG.md`, and `tasks/TASK_BREAKDOWN.md`.
- Allowed writes: `docs/adr/ADR-004-contract-conventions.md`, `schemas/README.md`.
- Forbidden writes: registry, task catalog, root plan, implementation/prototype code, concrete P0-CON-002..012 schemas.
- Lock: `SCHEMA`; Root owns lock allocation and no other schema worker may run concurrently.
- Required decisions: contract and document IDs; semantic/schema version fields; compatibility matrix; required vs optional fields; unknown-field handling by trust boundary; enum and union forward compatibility; canonical JSON and hashing; UTF-8; UTC timestamp shape; integer/rational units; Windows path representation and containment; null/omitted semantics; extension namespace; deterministic validation errors; migrations and downgrade refusal; atomic persistence; sensitive-field redaction; provenance/correlation IDs; size/depth/count limits.
- Required distinction: persisted configuration, immutable recipe/catalog, runtime observation, user-selected path, external-instance discovery and generated workflow cannot all share the same trust assumptions.
- Acceptance: downstream P0-CON-002..012 authors can implement without inventing conventions; hostile/unknown/newer contracts fail closed where they can affect execution, ownership, paths, artifacts or graph safety; harmless display metadata may be preserved according to an explicit rule.
- Evidence: cross-reference each binding decision to at least one downstream contract example and include a reviewer checklist. ADR status remains Proposed until Root acceptance.
- Forbidden shortcuts: no permissive “ignore all unknown fields,” no local-time timestamps, no floating-point frame/time math, no absolute private user paths in examples/evidence, and no mutable `latest/main` identifiers.
- Failure fallback: document unresolved choices and keep downstream schema tasks blocked; do not silently choose implementation-specific defaults.
- Unlocks after Root acceptance: P0-CON-002, P0-CON-003, P0-CON-005, P0-CON-007, P0-CON-008 and P0-CON-011.
