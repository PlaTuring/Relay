# P0-GOV-007 — Alpha no-self-update policy

- Owner: `/root/installer_plan_review`
- Objective: make “Alpha has no application/component self-update” a lintable build policy rather than a prose promise.
- Product boundary: the tool installs a version-pinned local environment and compiles workflows; MiniMax H3 generates media only after user Run. This task adds no generation or remote service.
- Accepted inputs: `AGENTS.md`, ADR-001, decisions D-005/D-016, optimized architecture, embedded-catalog plan.
- Allowed writes: `docs/adr/ADR-011-alpha-no-self-update.md`, `prototypes/phase0/no-self-update/**`.
- Locks: none.
- Forbidden actions: no network, package install, model/Comfy/GPU use, root manifest/lockfile edit, updater implementation, telemetry, remote catalog or writes outside owned fixtures.
- Required policy: Alpha contains no update service, background scheduler, update channel, mutable `latest/main` resolution, remote manifest/catalog lookup, silent component update, runtime package install, or “update all”. Manual installation of a newly signed application version is outside the running Alpha process.
- Required evidence: deterministic linter and clean/negative fixtures for forbidden dependency names, scripts/config keys/endpoints/channel/latest patterns and runtime download hooks; avoid naive prose-only false positives and document the scanner's limits.
- Acceptance: one command passes the clean fixture, rejects each negative fixture with a precise rule ID, and writes no external state. ADR specifies trigger conditions for the future TUF/equivalent update program.
- Failure fallback: keep Alpha without any self-update surface; new versions are separate signed manual installs.
- Unlocks after root acceptance: P2-INS-002 and the optional P0-ARC-008 PoC dependency.
