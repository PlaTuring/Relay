# QA-001 — Unit/contract test runner

- Owner on dispatch: Root-assigned worker after P0-ARC-005 acceptance.
- Objective: provide one deterministic, dependency-light repository command that runs all registered fast/offline unit and contract tests without model, ComfyUI, GPU, Desktop, VM or network access.
- Product boundary: test orchestration only. It must never generate media, launch a formal H3 job, click Run, call `/prompt`, download artifacts or mutate user/external state.
- Dependencies: accepted P0-ARC-005 and P0-CON-001.
- Allowed writes: `package.json`, `package-lock.json`, `scripts/test/**`, `tests/runner/**`, `docs/evidence/FAST_TEST_RUNNER.md`.
- Forbidden writes: product prototypes/modules, schemas, registry, main plan and existing evidence outside the assigned report.
- Lock: `ROOT-LOCKFILE`; Root must allocate it exclusively. Prefer Node built-ins and zero new production/runtime dependencies. Any dependency addition requires exact justification and lock/SBOM impact.
- Required design: checked-in allowlisted test manifest; exact executable + argument arrays with `shell:false`; per-test timeout; deterministic order; clear pass/fail/blocked/skipped distinction; bounded stdout/stderr capture; path/token/prompt redaction; exit nonzero on required failure; duplicate test ID rejection; no arbitrary command from fixture/environment; Windows Unicode/space repository path support.
- Lanes: default `fast` must be offline and dependency-light; optional locally-provisioned stack tests may be a separate explicit lane and cannot silently turn a missing prerequisite into pass. GPU/model/Desktop/VM/download lanes are forbidden in this task.
- Required negative fixtures: shell metacharacter/command injection entry, duplicate ID, missing executable, timeout, nonzero child, oversized output, private-path output and an entry that attempts forbidden GPU/model/Comfy/network lane.
- Acceptance: one root command passes twice from the current repository; negative runner fixtures return exact deterministic reason codes; process tree is cleaned on timeout; report lists included/excluded tests and prerequisites.
- Failure fallback: no root test command is advertised; preserve existing direct test commands and do not weaken their assertions.
- Unlocks after Root acceptance: QA-002 and a common test entrypoint for subsequent implementation tasks.

## Root acceptance command

From repository root: `npm test`. Expected exit `0`, deterministic lexical order, `passed=5 failed=0 blocked=0 skipped=0`; `node --test .\tests\runner\runner.test.mjs` separately reports 12/12 hostile runner tests.
