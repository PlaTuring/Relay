# P0-GOV-010 — Gate/critical-path review

- Owner on dispatch: Root-assigned governance reviewer; the worker never edits the live registry.
- Objective: produce the unique machine-readable gate catalog and verify that every production task has exact task and external prerequisites without false serialization or bypasses.
- Product boundary: governance and deterministic validation only. No download, ComfyUI launch, `/prompt`, GPU, model, media generation, installation or system mutation.
- Dependencies: Root-accepted P0-GOV-003 and P0-GOV-004; consume the 152-task WBS, accepted ADRs, external-gate list and current registry as read-only inputs.
- Allowed writes: `docs/architecture/GATE_CATALOG.md`, `docs/evidence/CRITICAL_PATH_GATE_REVIEW.md`, `tests/fixtures/governance/gates/**`.
- Forbidden writes: `tasks/registry.json`, `tasks/TASK_BREAKDOWN.md`, plans, schemas, product code and lockfiles.
- Locks: none.
- Deliverables: one unique G0–G11 catalog; task-to-gate/external-prerequisite map; critical-path report; valid and hostile gate fixtures; exact proposed Root registry delta. A worker cannot accept a gate or external Human decision.
- Required negative fixtures: duplicate ID/name, missing task, accepted gate with unaccepted requirement, active task behind a closed gate, unknown `EXT-*`, circular gate relation, gate self-unlock and conflicting critical-path claims.
- Acceptance commands from repository root:

  ```powershell
  node .\tests\fixtures\governance\gates\validate-gates.mjs
  powershell -NoProfile -ExecutionPolicy Bypass -File .\tasks\validate_wbs.ps1
  ```

  Expected: both exit `0`; the first prints deterministic valid/negative counts and the second starts with `WBS_VALIDATION_OK tasks=152`. Run both twice with byte-identical validator summaries.
- Evidence level: contract/gate topology may become `proven`; legal, signing, model, Desktop, GPU and release gates remain external or pending.
- Failure fallback: keep downstream task hidden/not-ready and report the exact unresolved prerequisite; never mark a gate accepted from prose.
- Unlocks after Root acceptance: authoritative scheduling for all post-contract and production implementation waves.
