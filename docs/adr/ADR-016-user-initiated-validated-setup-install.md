# ADR-016：用户主动下载并启动已验证的 Stable Setup

- **状态：** Accepted（产品所有者于 2026-09-01 明确授权）
- **日期：** 2026-09-01
- **适用范围：** Relay Stable 应用更新的单次“下载并安装”操作
- **依赖：** ADR-015 固定 Stable Release 发现、选择、下载与完整性验证合同
- **覆盖范围：** 仅覆盖 ADR-011、ADR-015、D-005 与 D-022 中“Relay 永不启动已下载安装程序”的绝对表述
- **不改变：** 产品/生成边界、后台更新禁令、远程组件 catalog 禁令、任意 URL/路径/命令 IPC 禁令、发布者身份与 Authenticode 边界

## 背景

Relay 1.0 已具有用户主动的 Stable Release 检查与 Setup 下载能力。原合同要求下载完成后只能打开所在目录或发布页，用户再手动运行安装程序。产品所有者现明确要求：当版本不一致时显示“下载并安装”；用户点击一次后，由 Relay 下载、验证并启动该版本的交互式 Setup。

该需求不是后台自更新，也不授权静默安装、远程组件替换或 renderer 执行任意程序。它是一个固定发布源、固定资产角色、固定受管目录和一次性用户意图闭包下的窄启动能力。

## 决策

Relay 可以在同时满足以下条件时启动 Stable Setup：

1. **用户明确发起。** 只有用户在“关于”页点击“下载并安装”后，当前操作才可检查、下载、验证并启动 Setup。启动时、切页、定时器、后台任务、托盘、服务、计划任务或远程通知都不得触发该流程。
2. **固定发布源。** 候选只能来自 ADR-015 固定的 `github-releases:PlaTuring/Relay:stable`，renderer 不得提供 owner、repository、Release URL、资产 URL、文件路径、摘要或命令。
3. **固定资产。** 只能处理 ADR-015 版本合同精确匹配的唯一 x64 Setup。Portable、源码压缩包、重复资产、额外安装包或名称不匹配的 EXE 均失败关闭。
4. **完整验证先于启动。** API 资产长度、HTTP 长度、最终落盘长度和流式 SHA-256 必须全部通过；摘要必须等于 GitHub REST 资产的严格 `sha256:<64 lowercase hex>` digest。失败、取消或不完整文件不得启动。
5. **受管文件唯一。** 可执行文件必须是下载服务本次原子发布到 `<dataRoot>/downloads/updates/<version>/` 的精确目标文件。启动前再次进行 containment、普通文件、非重解析点、文件名、长度和 SHA-256 校验；外部路径、符号链接、junction 或同名旁路均失败关闭。
6. **交互式安装。** 启动 Setup 时不传 `/S`、`/silent`、`/quiet`、`/VERYSILENT` 或任何参数；不拼接 shell 命令。Windows 安装界面与 UAC 保持可见，由用户完成或取消安装。
7. **一次操作只启动一次。** 同一时间只允许一个下载/启动事务；重复点击不得产生第二个下载或第二个 Setup 进程。状态必须区分下载、验证、启动失败和已启动。
8. **成功后再退出。** 只有 Windows 明确接受启动请求后，Relay 才可退出当前应用进程。启动被策略阻止、文件关联失败或系统返回错误时，Relay 保持打开并显示准确错误，不能显示成功，也不能退出。
9. **无通用执行桥。** native helper、preload 和 renderer 不新增任意路径、任意参数、任意命令或通用进程启动能力。执行授权只存在于 main process 的固定 Stable Setup 路径，并消费下载服务内部保存的受信状态。
10. **不改变组件。** 该 Setup 启动能力不能修改当前应用内嵌 component catalog，不能下载或安装模型、ComfyUI、节点、recipe、runtime 或社区组件，也不能触发 Run、`/prompt`、ComfyUI 队列或媒体生成。

“下载并安装”在产品文案中表示“下载并验证后启动交互式 Setup”，不表示静默、无人值守或保证安装成功。Setup 的实际安装结果由 Windows 安装程序负责，Relay 不伪造完成状态。

## 信任边界

GitHub 资产长度和同一 Release 信任域提供的 SHA-256 可以验证下载内容与所选资产一致，但不能建立独立发布者身份、仓库未被接管、元数据未被冻结或回滚的证明。ADR-015 的最高稳定版本、不回退和精确资产闭包继续适用。

未取得 Authenticode 时，Windows 可能阻止或提示未知发布者；Relay 必须把此类结果作为启动失败或交互式系统提示处理，不能绕过 Defender、SmartScreen、AppLocker、企业策略或 UAC。SHA-256 不替代 Authenticode。

## 可验收不变量

- 没有用户点击“下载并安装”时，网络请求数、下载任务数和 Setup 启动数均为零。
- 版本一致时不显示“下载并安装”，也不启动任何文件。
- 版本不一致且候选合格时，用户点击后只下载唯一 Setup；长度或 SHA-256 任一不符时启动数为零。
- 只有位于受管更新目录、完成原子发布且复核通过的精确文件可以启动。
- 启动参数数组为空；不存在 shell command string、通用 `exec`/`spawn` IPC 或 renderer path authority。
- 启动成功回调至多一次，随后 Relay 才退出；启动失败时退出次数为零并显示稳定错误码。
- 取消、断网、短响应、超长响应、摘要不符、重解析点、路径越界和并发请求都不会启动 Setup。
- 该流程不会调用 Run、`/prompt`、ComfyUI 队列或媒体生成能力。

## 被否决的方案

### A. 检查到新版本即后台下载或启动

**否决。** 版本差异只改变页面状态；必须等待用户点击“下载并安装”。

### B. 下载完成后静默安装

**否决。** 不传静默参数，不隐藏 UAC 或安装界面，不替用户确认安装选项。

### C. renderer 传入安装包路径

**否决。** renderer 只能请求固定的 Setup 更新动作；最终路径和验证证据完全由 main process 持有。

### D. 从下载目录选择任意 EXE 执行

**否决。** 只能启动下载事务内部记录并再次验证的精确目标文件。

### E. 先退出 Relay，再尝试启动 Setup

**否决。** 启动失败会让用户失去反馈。必须先确认启动请求成功，再退出当前 Relay。

## 重新评审触发

- 后台、启动时、定时、托盘、服务或强制更新；
- 静默/无人值守安装、自动确认 UAC、安装完成后的自动重启；
- 支持 Stable 之外的通道或 Setup 之外的可执行资产；
- renderer、preload、helper 获得任意 URL、路径、摘要、参数或命令权限；
- 下载/启动更新同时改变 component catalog、recipe、runtime、模型或节点；
- 宣称 GitHub SHA-256 提供发布者身份、代码签名或 TUF 等价保证。
