# MiniMax H3 Control Plane 全软件复审与抖音需求报告

复审日期：2026-08-29  
审查对象：`0.1.0-alpha.17` 与当前工作区源码  
结论：核心产品方向成立，适合继续内部 Alpha 与人工试用；在 P0 项关闭前，不建议作为面向普通用户的正式商业发行版。

## 1. 产品边界

本工具只负责：

- 检测、复用或安装 ComfyUI、MiniMax H3 模型及经过验证的可选组件；
- 根据本机硬件选择已验证配方；
- 校验用户输入并编译可编辑的 ComfyUI 工作流；
- 把工作流稳定交接到用户指定的 ComfyUI。

本工具不负责生成视频，不调用第三方推理 API，不提交 ComfyUI `/prompt`，也不自动点击 Run。正式视频和原生音频始终由 MiniMax H3 在 ComfyUI 中、由用户检查节点后点击 Run 生成。

## 2. 本轮已完成的用户可见改进

### 2.0 导航、导入规划与关于页

- “创建工作流”下方新增“导入 H3 工作流”；当前是无执行控件的诚实占位页，仅预告社区工作流本机兼容性体检。
- 左侧底部、LOCAL 标识上方新增“关于”；程序名称、构建版本与品牌状态从主进程 bootstrap 读取，HTML 不硬编码版本。
- 关于页暂时复用 H3 软件标识并保留作者 Logo/名称替换区，未虚构作者身份。
- 明确 Logo/作者品牌只属于软件界面，不进入视频、图片或音频；实际媒体仍仅由用户在 ComfyUI 点击 Run 后交给 MiniMax H3 生成。
- 页面切换只隐藏现有 DOM 视图，不重建创建工作流表单。

### 2.0.1 操作反馈改为主题化弹窗

- 移除页面底部固定的交接、保存和错误状态区，避免遮挡表单内容。
- 编译入口移到项目标题区，保存成功、工作流打开成功、仅保存未替换画布及操作级错误统一使用居中弹窗反馈。
- 工作流名称、提示词等可直接定位到字段的问题仍贴近输入框提示，避免弹窗打断填写。

### 2.1 工作流名称改为用户填写

- 在提示词上方新增必填的“工作流名称”。
- 名称用于 JSON 文件名和 ComfyUI 工作流标签。
- 程序不再根据提示词猜测名称。
- 名称不进入 H3 `ProjectSpec`，不会污染提示词或模型输入。
- 支持中文；自动去掉可选的 `.json` 后缀；拒绝 Windows 非法字符、保留设备名和空名称。
- 同名同内容可幂等复用；同名不同内容不会覆盖已有工作流，而是要求用户改名。

### 2.2 提示词框加入动态灰色中文示例

示例通过 HTML `placeholder` 显示：

- 只是灰色提示，不是输入值；
- 用户开始输入后自动消失；
- 不进入工作流、不计入 4000 字符、不参与命名；
- 随 T2V、FL2VA、Ref2VA、总时长和单段时长动态变化；
- 多段示例包含每一个真实时间边界；
- T2V/FL2VA 使用 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`；
- Ref2VA 示例保留官方需要的字段与标记，包括 `[reference generation]`、`fully_preserved`、`<Subject 1>`、`<Picture 1>`。

这解决了“只输入一句简单描述时，多段工作流不知道怎样写”的问题，但不会替用户自动扩写剧情。确定性分段仍只基于用户明确写出的镜头和时间边界。

### 2.3 结构化提示词与所选时长联动

- 只把紧跟 `[Shot N]` / `[镜头 N]` 标题的时间解析为切点；镜头正文、声景和配乐中的时间不会参与分段。
- 即使界面当前是单段，只要用户粘贴了官方结构化提示词，也会检查镜头时间是否超出所选总时长。
- 输入时检测最后一个镜头切点；若粘贴了 15 秒时间线但界面仍为默认 5 秒，会直接显示“改为 15 秒”按钮。
- 错误信息会指出当前总时长、具体镜头和越界时间，不再只显示泛化的“时间线无效”。

## 4. 全软件交叉审查

### 4.1 P0：正式发行前必须关闭

#### P0-01 后端静默记录用户已完成法律确认

界面移除繁琐授权步骤没有问题，但当前执行适配器仍把 `licenseAccepted`、`territoryAcknowledged`、`commercialAcknowledged`、`downloadConsent` 固定写成 `true`。这会记录用户并未实际作出的声明。

建议不要恢复三个或四个繁琐复选框，而是调整安装契约：程序不能伪造用户声明；下载按钮旁清楚展示官方来源、许可链接和组件清单，具体许可流程由正式发行前的法律审查决定。

#### P0-02 Windows 成品未签名

Setup 与 Portable 均为 `NotSigned`。面向普通 Windows 用户公开分发前，需要代码签名、干净虚拟机安装/卸载验证和发布清单闭合，否则 SmartScreen 与杀毒软件会显著增加流失和售后成本。

### 4.2 P1：高概率影响真实用户

1. **ComfyUI 实例身份绑定不足**：当前主要依赖固定的 `127.0.0.1:8188` 与前端能力探测，不能充分证明该端口就是用户配置的 ComfyUI。应绑定配置根目录、进程身份、启动时间或会话令牌，并在交接前验证节点和模型可见性。
2. **应用重启后的状态不完整**：界面可恢复“已安装/已绑定”配置，但受管启动上下文只保存在内存。重启后可能出现界面说已配置、适配器却无法启动或判断 Ref2VA/Turbo 的情况。
3. **同一安装根可并发写事务**：不同操作可以同时修改共享 manifest 或 YAML，存在丢条目的风险。需要安装根级互斥锁、原子写入，并启用 Electron 单实例锁。
4. **安装期间仍可重新扫描**：扫描可能清空正在显示的安装事务状态，而后台下载仍继续，导致查询、取消和恢复入口丢失。安装期间应禁用破坏性扫描，或让扫描只读并保留活动事务。
5. **断点续传磁盘预检过严**：恢复下载时仍可能按完整文件大小检查剩余空间，而不是按未下载字节计算，导致本可续传的下载被拒绝。
6. **ComfyUI Desktop 文案容易误导**：当前策略是下载并校验官方安装器，再由用户启动安装；不应把它描述成已经由本工具静默完成安装。
7. **中国网络可用性未完成全国性验证**：本机连通不代表不同运营商和地区都稳定。H3 模型已把国内来源放在前面，但 ComfyUI、FFmpeg、Desktop 仍需来源健康检查、换源续传和人工导入兜底。

### 4.3 P2：应进入后续质量迭代

1. 图片选择只检查扩展名和大小，还应验证文件魔数、实际解码结果和尺寸。
2. 界面提示词上限是 4000 个 UTF-16 字符，编译器按 32KB UTF-8 校验，两层限制应统一并对中文给出准确剩余额度。
3. 上层 Windows 路径校验比本地运行时弱，部分危险或不可用路径会拖到安装阶段才报错。
4. 安装状态查询出现一次临时错误就停止轮询；应有限重试，并明确区分“查询暂时失败”和“安装已经失败”。
5. 需要清理或更新过期的已完成事务 ID，避免用户误以为当前页面仍对应旧安装。

### 4.4 已确认可靠的部分

- 下载清单具备固定 revision、长度、SHA-256、断点续传、校验和失败恢复设计。
- 多段中文结构化提示词可编译成不同的 5/10/15 秒分段，不会把整段提示词粗暴复制到每个节点。
- ComfyUI 交接已有并发、脏工作流、关闭竞态测试。
- ComfyUI 交接会等待官方工作区恢复的 spinner 结束，并用本次唯一内存标记验证最终画布；旧标签晚到覆盖时只安全重载一次。
- 不同用户工作流不再继承同一个官方模板根 ID，而是按用户名称与内容生成稳定且不同的 UUID，降低标签身份冲突。
- 没有自动运行工作流，没有 `/prompt` 提交，没有第三方推理 API。
- 当前快速扫描在测试环境约为秒级，而不是全盘无边界扫描。

### 4.5 本轮尚未覆盖的真实环境

- 未实际下载几十 GB 全套模型；
- 未实际运行 H3/GPU 生成；
- 未完成干净 Windows VM 的安装、升级、卸载、重启测试；
- 未完成电信、联通、移动及不同地区的下载稳定性抽样；
- 未覆盖大量第三方 ComfyUI 整合包和自定义前端版本。

## 5. 抖音公开需求观察

以下观察日期为 2026-08-29。只查看公开搜索页和公开视频评论，没有登录、评论、点赞或抓取非公开数据。页面上的部分数字没有明确标注为播放量或点赞量，因此只作为热度信号。

### 5.1 评论中反复出现的真实问题

1. **硬件不确定**：用户反复询问 4060、5060 Ti、5080、5090、笔记本显卡以及不同内存组合能否运行、一次要多久。即使 32GB 显存，也有人在更长单段时遇到驱动掉线。
2. **模型和目录错误**：缺 VAE、模型放错目录、插件装了但 ComfyUI 看不到、固态空间不够、能否放机械盘，是高频问题。
3. **安装和版本维护**：没有 ComfyUI 基础的用户即使看完教程仍难完成；节点和内核更新后，用户大量时间花在修复工作流。
4. **长视频连续性**：用户关心每段能生成多久、第二段爆显存、人物和大场景怎样保持一致、尾帧怎样接下一段。
5. **提示词格式**：用户直接询问是否需要先转成 H3 官方结构，或能否直接输入普通提示词。
6. **国内下载**：用户需要国内可访问来源、断点续传和明确的模型放置位置，而不是拿到一个海外链接后自行处理几十 GB 文件。
7. **“求工作流”很多，但 JSON 本身付费价值低**：公开评论大量索要工作流，说明需求强，也说明单卖 JSON 很容易被免费资源替代。

### 5.2 市场判断

市场存在，但竞争已经很强：中文整合包、启动器、ComfyUI Manager、H3 导演台、付费资源站和“让 Codex 帮忙安装”都能解决一部分问题。

因此差异化不能只是“又一个 H3 工作流”或“又一个整合包”，而应该是：

> 可验证、可恢复、兼容现有环境、面向中国网络，并能在打开 ComfyUI 前把错误说清楚的 MiniMax H3 本地配置与工作流交付工具。

用户更可能为可靠性、节省时间、国内下载、版本维护和售后诊断付费，而不是为模型或 JSON 文件本身付费。这是根据公开评论和竞品反馈作出的市场推断，不是实际销售数据。

## 6. 建议功能路线

### P0：先把主链路做成“第一次就成功”

1. 关闭静默法律声明、完成代码签名和干净 VM 验证。
2. 安装根级事务锁、Electron 单实例锁和原子 manifest 写入。
3. 绑定正确的 ComfyUI 实例，并持久化受管启动上下文。
4. 工作流打开前检查模型、VAE、文本编码器、自定义节点、版本和实际可见性。
5. 国内源健康检查、自动换源续传、人工本地文件导入。
6. 中文错误翻译：明确“原因、影响、下一步”，同时保留原始错误。

### P1：形成明显差异化

1. **硬件配方页**：显存、内存、驱动、精度、分辨率、单段长度、预计用时和 OOM 风险联动；只把实测配方标为“推荐”。
2. **工作流健康检查**：打开前列出缺失项、官方来源、准确目录和兼容原因；支持一键重新绑定已有模型。
3. **长视频分段编辑器**：每段独立提示词、可选独立参考图、上一段尾帧接下一段首帧、人物与场景连续性锁。程序只做结构化编辑和确定性编译，不替用户创造剧情。
4. **多 ComfyUI 环境**：支持 Desktop、Portable 和常见整合包，安全共享模型而不是复制几十 GB。
5. **生命周期管理**：复用现有 ComfyUI、避免重复启动、正常关闭、再次导入时安全加载。
6. **离线诊断包**：导出前清除提示词、用户名和私人路径，便于售后按错误码定位。

### P2：验证来源和许可后再加

- 本地视频放大、补帧、脸部修复作为明确可选组件；
- 工作流历史、收藏、复制和版本管理；
- 只读导入社区工作流并分析依赖，不自动执行未知节点；
- 工作流健康评分，但评分依据必须透明；
- 面向工作室的多机器配置导入导出。

不建议短期堆叠“角色替换、动作迁移、无限时长”等未经完整验证的社区功能。也不应加入自动提交队列或自动生成视频，因为这会越过本产品明确边界。

## 7. 推荐商业方式

- 免费核心版：硬件检测、绑定已有环境、官方工作流编译、基础健康检查。
- 一次性 Pro：可恢复安装、国内下载策略、多环境、备份回滚、高级诊断和离线缓存。
- 可选售后：远程诊断或企业部署，不按单个模型文件收费。

公开竞品评论中已经出现“付费后入口仍难找、网盘仍慢、缺一个文件卡一天”的抱怨。因此透明的一次性授权、明确的组件来源和真正可恢复的安装流程，本身就是竞争优势。

## 8. 下一轮建议验收顺序

1. 先修 P0 与前五项 P1 工程缺陷。
2. 在两台干净 Windows VM 做首次安装、重启、升级、卸载、断网恢复。
3. 在三类真实环境验证：官方 Desktop、Portable、常见中文整合包。
4. 选择 16GB、24GB、32GB 三档显卡，建立可复现的硬件配方表。
5. 找 5—10 名没有 ComfyUI 经验的用户，只给软件不给教程，观察能否完成：检测 → 复用/安装 → 编译 → 打开 → 在 ComfyUI 点击 Run。

最终验收标准不是“界面能点”，而是小白不需要理解模型目录和节点连线，也能知道哪里出错、怎样恢复，并且工具从始至终不替 H3 生成视频。
